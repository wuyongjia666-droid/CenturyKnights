# 百年骑士 v9.2 试玩审查：按优先级排好的问题清单

审查日期 2026-10-12，基线是 `main` 的 `c1f6b304`（#134）。文中行号都以这个提交为准。

本文只记录问题、根因和修复方向，不改任何游戏代码。实现交给 playforge。

## 怎么查的

- **文档**：读了 `docs/design/` 下全部 16 份。重点是：
  - `v92-upgrade-proposal.md`（下称"提案"）
  - `combat-rules-v92.md`、`injury-v92.md`
  - `bloodlines-v89.md`、`fertility-v92.md`
  - `story-bible-v92.md`、`story-player-v92.md`、`ch0-novel-arc-v92.md`
  - `balance-v92.md`

  流与文件的归属，按 `docs/plan/audit-v92.md` §4.1。
- **代码**：逐条对照，找到根因所在的文件和行。
- **复现**：用 Godot 4.3 跑临时探针。逻辑用 headless 模式跑，截图用 xvfb 按 1280×720 拍。探针脚本放在仓库外，没有提交。另外跑了 `python3 tools/ci/portrait_bank_index.py`。
- **术语**：文中"实测"指探针跑出来的数。"推断"指只读了代码，没有在导出包或真机上跑过。

**优先级定义**

- **P0**：满足以下任一条：
  - 主线走不下去；
  - 存档数据被破坏；
  - 用户已经确认、而且在前期必经路径上。
- **P1**：玩家还能绕过去，但满足以下任一条：
  - 和文档相悖；
  - 明显误导玩家；
  - 破坏经济；
  - 让后期进度丢失。
- **P2**：打磨、文案、数据清洗、测试缺口。

## 一、结论

1. **主线路由坏了。** 这一条不在用户报的五条里，却是第 5 条的根因。
   - 第零章结束后，城堡上的「继续主线」永远打开第零章末拍，第一卷 8 章一章都进不去。
   - 舆图（`e1_04`）、委任榜（`e1_08`）、工坊、祠堂、联姻廷的解锁旗标，都挂在第一卷的战斗上，所以全部永远锁着。
   - 玩家觉得"委托榜和世界地图不存在"，是因为在这个版本里它们确实打不开。
2. **修好路由后还有第二堵墙。** 40 个卷章的末拍都没有按钮，返回键又被全局暂停菜单拦截。玩家会卡在每一章的最后一句。
3. **立绘配错（用户问题 1）是三层原因叠在一起：**
   - 基因库清单和已渲染底板的键对不上：清单 1600 个桶，只有 20 个有图。
   - 兜底的 hireuniq 选脸只分性别，不看年龄。
   - 男性脸池里混着约 4% 的白须老人脸；槽位永不释放，酒馆免费刷新会把池子刷空。

   另外，婴儿在整条取图链里没有一张婴儿图。
4. **孕期三个月（用户问题 3）是文档写的，代码照做。** `fertility-v92.md` 和提案 §4.7 都明文规定了三个月。
   - 要按用户期望改成随机约十个月，必须先改文档，再改代码、测试、种子 91 门禁和第零章时间线。
   - 另外，16–32 岁受孕不掷骰；玩家家族一辈子只会在婚礼那一刻怀一次。
5. **婚仪日志叠字（用户问题 2）是标签用错了地方。**
   - 整段婚礼结果被塞进一条 22px 高、本来不换行的说明标签。代码事后才打开换行，却不改位置和高度。
   - 面板 112px 高，而且会裁剪，所以第二行被切掉一半，第三行以后看不见。
6. **族谱入口难找（用户问题 4）有三个原因：**
   - 首年入口表漏掉了故事圣经要求的「联姻」「族谱」，换成了「设置」「旗塾」。
   - 族谱要等孩子出生才出现，出现时只是导航栏里一行 11 号字。
   - 城堡中间的三张卡里也没有族谱入口。
7. **另有四处要优先处理：**
   - 读档后人物 id 会撞号，新角色会覆盖存档里的人。
   - 开局全员 hp 未满，被算成"伤病 3"；祠堂开放前又没有任何回血途径。
   - 出战编队的仗可以无限重复、不花时间，每场 +35 银。第一年的紧银设计因此失效。
   - 剧情对白里 35.7% 的台词配的是团长的脸。老旗手、斥候，以及 5 个反派、5 个配角，都没有自己的立绘。

战斗规则抽查没有发现偏差。地形表、命中与伤害常量、派生属性公式，三者在 `combat-rules-v92.md`、`battle_rules.gd`、`character.gd` 里一致。战斗文档缺的只是生命值公式和战间回血，见第六节。

## 二、用户已确认的五个问题：根因

### 问题 1：19–22 岁候选人和 0 岁婴儿配了白胡子老人立绘（对应 P0-4）

**取图顺序。** `project/scripts/art/unit_art.gd` 的 `portrait()`（469 行）依次尝试：

1. 基因库单人图
2. 基因库 Plan A 桶图
3. 有名角色图
4. hireuniq 农场脸（768 个槽）
5. v8 半身
6. v84 按年龄的 geno 图
7. 程序生成

酒馆候选人、联姻对象、新生儿都没有有名角色图，所以实际只看 Plan A 和 hireuniq 两层。

1. **Plan A 基因库实际没有生效。**
   - **数量**：
     - 清单 `tools/farm_queue/genome_bank_v92.json` 有 1600 个桶。
     - `project/assets/art/portraits/genome/bank/` 里有 1595 张图：五个年龄段各 319 张，大、中、小三档 webp 都齐。
     - 两边能对上的键只有 20 个，每个年龄段 4 个。
   - **CI 没拦住**：`python3 tools/ci/portrait_bank_index.py` 输出 `BANK COVERAGE manifest=1600 with_plate=20 plates_outside_manifest=1575`，结论仍是 `BANK INDEX PASS`。
   - **原因**：
     - 清单是由百年模拟的个体生成的（覆盖种子 1101–1120）。开局抽签一变，桶键就全部重算。
     - `balance-v92.md` 67 行记过一次 1595 → 1605 的重写，并要求美术流"按新清单出图，不要沿用旧桶"。
     - #127 重写第零章后，清单又变成 1600 桶，但没有补投，也没有重新映射。
   - **后果**：
     - `CKPortraitBank.match_identity()` 的身份命中约 77%，但 `_load_plate()`（`portrait_bank.gd` 400–403 行）找不到文件，返回 null，于是直接落到 hireuniq。
     - 实测只有 0.9% 的角色真正拿到桶图。
2. **hireuniq 选脸不看年龄。** 见 `unit_art.gd` 的 `_face_uid()`，953–1000 行。
   - **年龄候选被作废**：函数先按 `_farm_tags_for()`（918 行）收集按年龄和职事打标签的候选槽，例如 child、youth、elder。紧接着 975、981 行的 `prefer.assign(FARM_FACE_SLOTS_F / FARM_FACE_SLOTS_M)` 把整个列表覆盖成整个性别池。
   - **按年龄挑的槽轮不到**：
     - 代码随后在列表前面插 3–5 个按年龄挑的槽。
     - 但起点是 993 行的 `h % npref`，在大约 270 个槽里随机取。
     - 前插的槽几乎轮不到，实际效果就是"在性别池里随机挑一张"。
   - **前插列表本身性别错**：
     - 男童 `[754, 154, 354, 554]` 里的 154、354 在女性池。
     - 男青年列表里的 360 在女性池。
     - 女青年列表里的 161 在男性池。
3. **男性池里混着老人脸。**
   - `FARM_FACE_SLOTS_M`（12 行）有 273 个槽，其中约 11 个是老者，约占 4%：
     - 白须：165、253、341、429、517、765；
     - 秃顶：216、304、392、480；
     - 另有 766。
   - 池里还有标签错的图：77 标 elder，画的却是年轻女性。另有一张品红色坏图 760。
   - 女性池里也有标 elder 的槽（57、145、233、321、409、497）。女性候选人第一次分配时，有 2.1% 落在这些槽上。这几张这次没有逐张目检，不确定是不是真的老人脸。
4. **槽位永不释放，刷新免费无限。**
   - `_face_owner` / `_face_assign`（8–9 行）是静态表，人离开后也不回收。
   - 酒馆的「刷新候选 ↻」（`tavern.gd` 24–26 行）不花钱、不限次数。
   - 实测：
     - 槽表还空着时（相当于开局第一次进酒馆），18–32 岁候选人里 2.6% 是老人脸。只看男性是 4.4%，只看 22 岁及以下的男性是 3.7%（3000 个样本）。
     - 连续刷新到第 155 次，男性开始分到池外的槽。
     - 720 个候选人里，32% 分在池外。池外是 768 槽全表开放寻址，不分性别和年龄。
     - 只刷了 6 次，就复现出一张 30 岁男性配白须槽 429 的卡（截图 09）。
5. **婴儿没有婴儿图。**
   - hireuniq 里没有婴儿脸。Plan A 的 320 个婴儿桶里，只有 4 个有图。
   - v84 按年龄出图的分支排在 hireuniq 后面，而 hireuniq 总能分到一个槽，所以这个分支永远走不到。它本身也只有 youth、heir、mid、elder 四档，没有婴儿。
   - 实测 300 个新生儿：
     - 全部走 hireuniq；
     - 1.7% 是老人脸，其余多是成人脸；
     - 也会配错性别。截图 05 是一个 0 岁男婴配了成人女脸，槽 354。
6. **单人图会跨年龄段回落。**
   - `genome_portrait.gd` 的 `_stage_names()`（448–457 行）在找不到本阶段单人图时，会按距离回落到其他所有阶段，婴儿最终也可能用到 elder 阶段的图。
   - 这是照文档做的。`bloodlines-v89.md` 383 行写的是"当前段还没画出来时用最近的一张"，没有限定最远能回落到哪一段。
   - 仓库里的单人图目录现在是空的，所以这一条暂时不触发。一旦开始出单人图就会出问题。
7. **可能的额外原因（未实测，请在试玩设备上核对）。**
   - `texture()` 还会读 `user://genome_portrait_cache/<id>_<阶段>.png`。`bloodlines-v89.md` §6 规定单人图"按 `unit_id` 入库"。
   - 现行代码已经不往这个目录写图，但从旧版本升级的设备上可能还留着旧图。
   - 人物 id 只是序号（例如 `hire_4`），每一局都会重复；再加上上一条的跨阶段回落，新角色可能读到旧档里另一个同 id 角色的老年图。

修复方向见 P0-4。导出包里的问题见 P1-9，数据清洗见 P2-3。

### 问题 2：婚仪结束后左下角日志叠字、被截断（对应 P0-5）

- **面板和标签**：`project/scripts/hub/marriage.gd` 104–111 行。

  - 说明标签 `_msg`（节点名 RiteExplain）放在 (12, 80)，尺寸 576×22。它设了 `autowrap = OFF`、`clip_text = true`，本来只放一行说明。

  - 家训与嫁妆；
  - `check_ambitions()` 返回的志向达成。

- **结果**：

  - 第二行被切掉一半，看上去像叠字；第三行以后完全看不见。
  - 截图 04 和 `crop_marriage_rites` 里能看到「…旗又升 / 高一寸。堡志「家训既立」达成」被切。
- **会让它更乱的两处**：

  - 窄屏布局把 `_msg` 放进 78–92px 高的面板，更容易被切。
- **提案早有要求，没有做**：提案 §4.7（714–736 行）和 P0 清单（921–922 行）要求用"婚后印"替换这一句：
  - 一张印，写两国与血律、双方姓名、聘银、家训、嫁妆、妊娠月数；
  - 第零章里，印上的按钮写「带回第零章」。

### 问题 3：婚后怀孕写死约三个月分娩，是否怀孕也不随机（对应 P0-6）

- **代码和文档一致，是文档本身和用户期望不符。**
  - `fertility-v92.md` 写的是：
    - 默认满 3 次月结分娩，快速家族 1 次；
    - "仍是百年压缩，而不是现实的四十周"；
    - 16–32 岁受孕率是 1，"不抽随机数"。
  - 提案 §4.7 的婚后印也写着"常速是三个月"。
- **代码位置**：

  | 位置 | 内容 |
  |---|---|
  | `project/scripts/characters/family_state.gd` 167–168 行 | `TERM_MONTHS := 3`、`FAST_TERM_MONTHS := 1` |
  | 同文件 285–321 行 | `term_months`、`fertility_of`、`conception_rate`、`begin_pregnancy`（存的是 term − 1） |
  | `project/autoload/calendar.gd` 110–115 行 | 月结倒计时，减到 0 以下时调用 `Lineage.birth_child` |
  | `project/autoload/lineage.gd` 92–101 行 | 婚礼当场调用 `begin_pregnancy`，文案用 `fertility_due`「约 %d 个月后分娩」 |
  | `data/locale/dynasty.csv` | `fertility_term`「孕期三月」 |

- **婚后是否怀孕，事实上是确定的。**
  - 联姻对象复用酒馆生成器，年龄 18–32（`character_factory.gd` 97、113 行）。团长 22 岁。
  - 双方都落在 16–32 岁区间，受孕率为 1，不掷骰，所以婚礼当场必定怀孕。
- **玩家家族只会怀这一次。** 玩家这一侧只有 `Lineage.marry` 会开始妊娠，没有任何按月受孕的规则。实测婚后 36 个月内没有第二胎。
- **百年模拟用的是另一套规则。**
  - `scripts/sim/campaign_sim.gd` 的 `_try_child()`（178–194 行）在子女少于 3 个、年份是 4 的倍数时，直接写 `pregnant_months = 1`，两次月结就分娩。
  - `fertility-v92.md` 交接给 S05 的"改调 `begin_pregnancy`"没有做。
- **实测**：婚礼当月之后，正好第 3 次月结分娩。
- **第零章的时间线绑在短孕期上。**
  - `ch0.json` 的 0.5 拍「初啼」，台词一开口就说"旗下有了哭声"，按钮却是「让月份走到孩子落地」。
  - 每按一次推进 1 个月，要按 3 次孩子才出生。孕期改成约十个月后，就要按十次。

### 问题 4：从城堡主界面不知道族谱在哪里进（对应 P0-7）

- **入口表和故事圣经不一致。**
  - `story-bible-v92.md` 文末的交接（418 行）写的是：第一年真正教过的入口不超过六扇，即战役、名册、酒馆、联姻、族谱、沙漏。
  - `project/data/story/tutorials.json` 2 行的 `year_one` 却是 deploy、roster、tavern、hourglass、settings、train。少了联姻和族谱，多了设置和旗塾。
- **族谱要等孩子出生才出现。** 同文件 10 行是 `{"flag": "child_born", "entries": ["lineage"]}`。第零章 0.5 拍会自动跳一次族谱页；之后玩家只能在导航栏里自己找。
- **出现了也很难看见。**
  - `castle_hub.gd` 357–364 行的 `_nav_item(compact)`：条目高 20px、字号 11，文字是"编号 标题"，副题只放在 tooltip 里。
  - 新解锁的条目没有任何提示。截图 06 里，族谱和授旗礼只是以小条目出现在「家族」组。
  - 城堡中间三张卡里，#03「联姻与传承」只链到联姻廷（160 行），没有族谱按钮。
- **联姻廷要等 `e1_07` 才进导航**（`tutorials.json` 8 行）。`e1_07` 因为 P0-1 永远到不了，所以导航栏里永远没有联姻廷，只能从 #03 卡片进去。

### 问题 5：找不到委托榜和世界地图，前期感觉这两样都不存在（对应 P0-8）

1. **直接原因是主线路由坏了（P0-1）。**
   - 舆图要 `e1_04_fought`，委任榜要 `e1_08_fought`（`tutorials.json` 5、9 行）。
   - 第一卷进不去，这两个旗标永远不会置位。
   - 舆图里各城的「委托」页签（`atlas-cities-v87.md` 写的每城委托榜）也跟着锁住。
2. **就算修好路由，也要很久才见到。** 要打完第一卷第 4 章才有舆图，打完第 8 章才有委任榜，期间没有任何"何时开放"的提示。被锁的条目是直接隐藏的（`castle_hub.gd` 101 行），不是显示成灰色。
3. **界面在暗示它们存在，但点不进去。**
   - 导航栏的「舆图」分组标题照样显示，下面是空的（截图 01）。
   - 待办芯片显示「可交付委托 11」（`todo_center.gd` 40 行），数的是 `GameState.quests` 的整张目录。
   - 「内政 16」角标把锁住的工事和委托也算了进去。
4. **叫法不统一。** 按钮叫「委任榜」（`strings.csv` 的 `btn_quests`），芯片叫「可交付委托」，舆图的 tooltip 叫「跑图 · 城镇 · 委托」，文档里叫「委托榜」。玩家在找"委托榜"和"世界地图"，界面上写的却是"委任榜"和"舆图"。

## 附录 A：复现方法

**各问题怎么复现**

- **主线路由**：新开局，走完第零章。也可以在探针里置 `hub_open`、`battle_done`、`recruited`、`married`、`child_born`、`harvest_done`、`chapter0_done` 这些旗标，再设 `chapter0_beat = "0.6"`。然后在城堡点「继续主线」，打开的是第零章的 0.6。
- **末拍没有出口**：把 `chapter_player.tscn` 的 `chapter_path` 设成 `era1_01.json`，跳到 `end` 拍。读完对白后，`action_labels()` 是空的。
- **立绘**：在酒馆连续点「刷新候选 ↻」，用 `UnitArt.portrait_kind(c)` 和 `_face_uid(c)` 统计。新生儿可以在婚后连续调用 `Lineage.birth_child` 来批量生成。
- **婚仪日志**：第零章 0.4 拍 → 联姻廷 → 走完四步誓约 → 看左下的「RITES // 婚仪」面板。
- **孕期**：婚礼后每次 `Calendar.advance(1)`，看第几次月结出现 birth 事件；之后再推 36 个月，看有没有再孕。
- **id 撞号**：新开局，招募一名酒馆候选人并存档 → 重启进程、读档 → 刷新酒馆，把新候选人的 id 和已有 id 比一比。
- **hp**：新开局后打印 `roster()` 里每人的 `hp` 和 `max_hp`。
- **对白立绘**：统计 `data/story/chapters/` 下 41 个章节（不含 lint 样例 `lint_clean.json`）里每句台词的 `speaker`，按 `_speaker_portrait()` 的分支归类：
  - 在同伴表里的，走表情图；
  - 旁白、掌柜、管事、稳婆、春令使者、盟友亲属，用旗帜；
  - 老旗手、斥候，以及其余没有角色实例的说话人，用团长立绘。

**探针怎么写**

- `--script` 模式下 autoload 的全局名不可用。做法是写一个 `extends Node` 的临时脚本，挂进一个临时 `.tscn`，然后运行 `godot --headless --path project --scene <临时场景>`。autoload 用 `get_node("/root/GameState")` 取。
- 截图用：`xvfb-run -a -s "-screen 0 1280x720x24" godot --path project --rendering-driver opengl3 --audio-driver Dummy --scene <场景>`。
